# Contributing

Propose changes through issues or pull requests. Describe the user situation and why the current material is insufficient. Cite primary sources for factual assertions and identify dates/market scope where relevant.

Keep English as the primary language. Language-specific additions should explain terminology and source differences. Do not submit private personal records, confidential client data, speculative allegations or fabricated observations.

Run `python3 tools/validate.py` before submission. Documentation/templates/artwork use CC BY 4.0; validator changes use MIT. Do not imply provider endorsement or guaranteed outcomes.

## Choose a contribution route

- [Bug or documentation error](https://github.com/mhdteto/executive-authority-playbook/issues/new?template=bug_report.yml): include a release tag or commit and a minimal public/fictional reproducer.
- [Feature request](https://github.com/mhdteto/executive-authority-playbook/issues/new?template=feature_request.yml): state the task, example and proposed behavior.
- [Source or methodology proposal](https://github.com/mhdteto/executive-authority-playbook/issues/new?template=source_proposal.yml): provide the specific claim, publisher, dates, market, relationship and limits.

Run the documented validation and preserve the distinction between observed, supplied, inferred and unknown. See the [connected fictional workflow](https://github.com/mhdteto/authority-architecture-system/tree/main/examples/fictional-workflow) for an example.
